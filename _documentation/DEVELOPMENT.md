# Local development

The application is an independent static ES-module package in `_application/`, with the retained WebGL renderer and no third-party JavaScript dependencies.

Pass008 adds an independently rebuildable Rooms publication package in `_hosting/`. Use `npm --prefix _application run build:rooms` and `npm --prefix _application run test:hosting`; see `HOSTING.md` for migration and publication gates. The original preview remains application-only. `scripts/preview-projects.mjs` serves the staged discovery-page files and a separately saved public API snapshot for local QA; it does not run the Projects backend or access D1.

From the project root:

```sh
npm --prefix _application run build
npm --prefix _application test
npm --prefix _application run dev
```

The preview binds only `127.0.0.1:4201`. Set `TRANSPLANT_PORT` to another free port (or `0` for an ephemeral port). It refuses writes, traversal and non-allowlisted files. An occupied port fails; never stop a process to take its port. Sandbox EPERM on loopback requires a permitted local preview, not disabling or changing unrelated services.

Build source is `page.mjs`; `index.html` is generated. The build verifies the explicit `runtimeAssets` list in `scaffold.mjs`. Every browser import must itself be allowlisted. Build/test tools resolve their root to `_application/`, independently of the caller's working directory.

Python utilities and register operations use `/Users/Shared/7_PythonApps/99_venvs/.venv1/bin/python` (`1_social`, Python 3.14.3). No Python packages are needed for the current app. The explicitly designated shared SQLite register is the coordination store, not an application backend; no PostgreSQL application database is needed at this stage.

## Content boundaries

- `data.mjs`: rooms, exhibits, authored objections and main response content; integrates branch content and the pure reasoner through response/review/export helpers.
- `paths.mjs`: follow-up questions and the six two-way checks. No browser state. Conditions use validated `all`/`any`/step-choice leaves.
- `reasoning.mjs`: pure validated dependency engine, active plans, context snapshots, stale/inactive retention, scoped checks and signature-bound explanations.
- `stepsIn(room)` returns the complete static reading catalogue; `stepsIn(room, answers)` returns the active interactive path. Use `currentChoice`, not a raw answer lookup, for progress or feedback.
- `evaluation.mjs`: independent room 01 on evaluative standards, evidence, subjectivity and rule application; five decisions and four selected-source records.
- `fairness.mjs`: room 02 (where moral feelings come from): animal, infant and cross-cultural evidence, its steps and the empirical source records.
- `values.mjs`: the twelve opening value questions and the three principles per room, with their intake links, `fits`/`strains` answer links and notes. No cap, weighting or worldview inference.
- `journey.mjs`: pure crystal inspection/toggle, opening and closing value answers, intake pre-selection (`intakePicks`), notes and private record helpers with `ts_ms`.
- `presentation.mjs`: shared evidence, case and source rendering.
- `sources.mjs`: source IDs, URLs, authors, source type, locators, access levels and limits. The larger corpus is in `ARGUMENT_CORPUS.md`.
- `presentation.mjs`: shared numbered exhibit points and evidence/case/source rendering. Every room reference offers a collapsed account of the source's support, actual access and limitations; source presence does not imply endorsement of MORARG's conclusion.
- `art.mjs`: active topical diagram metadata plus inherited artwork provenance; JPEGs are unchanged.
- `topical-art.mjs`: twelve authored SVG argument diagrams, generated by the build. They represent no measured quantities.
- `rooms.mjs`: procedural hilltop gardens, sea/island scenery, picking targets, bridge-shaped portals and neutral animation. Internal theme IDs retain their original names. `layoutRoom` defines the stable interaction contract independently of scenery; freestanding boards use the existing art-slot IDs and dimensions. Keep scenery clear of targets and do not infer argument weight from visual size or planting.
- `app.mjs`: navigation, sequential choices, feedback, exit review, optional values, editable reasons, explore/stress-test entry and private export. `?view=controls#hub` deliberately bypasses WebGL; all content and values stay usable. Phone entry begins with the reading version; opt-in opens the room overview directly.
- `page.mjs`: full static reading alternative, including every response rationale and source access note.
- `scaffold.mjs`: `__version__` and exact browser asset boundary; `package.json` mirrors the version.
- `_tests/`: feature tests; no version-specific test names.

The original `source-manifest.json` and `verification.json` are extraction receipts from the copied skeleton, not verification of this build. Their scope is labelled in place. Current pass reports and screenshots are under the project `_output/` folder. The old documentation screenshot is labelled as inherited in the transplant guide.

Before finishing a change, rebuild, run the feature tests, and inspect desktop/narrow entry, one flagged and one unflagged choice, revision, room exit override, room travel, case evidence, crystal inspection/keep/release, working-note retention, the response summary, and the reading version. Exercise at least one nested branch, same-case conflict, compatible near miss, changed-mind explanation, A→B→A stale response and cross-room revision. Acknowledgement is not logical resolution; check current and retained export sections separately. Verify export data through pure helpers; avoid a browser download outside the project during automated validation. Record exactly what was checked. Do not infer live deployment from a successful local preview.

## Room movement regression checks

Use the actual WebGL view without `?view=controls`. Enter `#hub`, close the room card, hold W, drag to look, and click unobstructed ground to walk. Verify the scenery and labels move while the stage and canvas retain their full width. Travel through the exit review into another room and repeat, including at phone width. Check the console and capture the visible result. Controls-only checks cannot cover this renderer/layout path.

Pass015 reproduced the first-movement failure: the comparison badge's global `.moved` selector changed `#stage.moved` to `inline-block`, collapsing both stage and canvas from 1265px to 0px. The scoped `.comparison .moved` selector preserves the badge and the room. Future presentation rules sharing a state class must remain scoped to their component.

## Illustration sources

`ILLUSTRATION_PROMPTS.md` provides the master reference, twelve optional atmosphere plates, twelve symbolic paintings and five reusable environment/material prompts. Each prompt is self-contained for the Operator's rendering workflow. `VISUAL_ASSET_MANIFEST.json` records all thirty as `planned_unrendered`, with `runtime_loaded:false`; these are plans, not files the browser expects.

Select a master render before producing the rest so lighting, materials and botanical style stay coherent. Preserve Operator originals in `_input` without editing them. Make any reviewed, derived runtime copies inside `_application`, add only those real files to `runtimeAssets`, and update manifest status only after integration is verified. Keep decorative painting slots separate from `morality-*.svg`: generated imagery cannot replace authored argument text, diagrams or evidence. Verify crops, actual alt text, responsive contrast and asset weight against the chosen render. A future illustrated backdrop should preserve depth cues and all existing targets rather than obscuring the walkable scene.
