# MORARG illustration prompt pack

Pass005 planning document for MORARG Build 0.5.0 / argument edition 4 and its optional hilltop-and-archipelago visual direction. This pack contains 30 independently pasteable image prompts: one master reference, twelve room backdrops, twelve symbolic exhibit paintings and five reusable material/environment assets.

All 30 assets are **planned_unrendered**. These are planned image sources only: none has a current runtime slot or is loaded by the procedural 0.5.0 application. Scene backdrops are optional future atmosphere images; symbolic paintings are optional future secondary art and are not restricted here to a wall-only runtime. Every `morality-*.svg` remains an authored informational argument diagram and must stay intact and separate from any generated painting.

## Visual bible

Use this visual bible in full: painterly gouache-and-watercolor landscape art with visible soft brushwork and fine paper grain, believable scale and spatial depth, calm clear daylight, and a lush, botanically varied temperate-to-subtropical archipelago. Let rocky green hills, olive and citrus terraces, laurel, pines, ferns, meadow plants and salt-tolerant coastal growth vary from island to island. Use warm pale limestone, weathered oak, restrained aged-copper accents, sea-glass turquoise water, soft blue skies, and a quiet humane mood. Keep forms spatially coherent and compatible with the approved master establishing image; give each island its own identity and equal visual dignity. Avoid photorealism, fantasy, moral rankings, scales, verdict symbols, scoreboards, trophies, halos, victors or victims, text, letters, numbers, labels, signage, logos, maps, flags, charts, diagrams, axes, legends, watermarks, UI, frames, borders, collages, panels, factual or historical reconstruction, implied empirical evidence, sensationalized victims or abuse, or a primate/research experiment; never demonize realists, critics or dissenters. Make one unified image.

## Render workflow

1. Paste the master establishing prompt first and render one image. Review it, select the approved reference, and save the original as `morarg_master_archipelago_establishing_planned.png` in user-supplied `_input/` when it is provided. Keep user-supplied originals in `_input/` unchanged.
2. Use the approved master as a reference when available. Each later prompt also contains the complete visual bible, so a missing attachment is not a blocker. Render the hub backdrop and hub painting as a priority hero pair first; use them to review the look before rendering the remaining eleven backdrops and eleven paintings. Then render the five reusable assets.
3. Save each original in user-supplied `_input/` with its exact `planned_filename`. These filenames describe planned source assets; no app file references them. Ask for one image per prompt: no contact sheets, triptychs, in-image text, labels or captions.
4. Inspect every result for unwanted text, wrong aspect ratio, unintended factual details, low contrast, visual hierarchy or a broken transparent background. Revise its draft alt text to match the actual image before any future integration.
5. Keep the status `planned_unrendered` until the file exists and has been reviewed. A later authorized integration pass may derive implementation copies in `_application/`; do not move, edit or overwrite the `_input/` originals. Backdrops need a future decorative slot; paintings need future secondary slots; current procedural rooms and authored SVG diagrams remain in place.

The room IDs, room names, introductions, diagram IDs and slot envelopes below were checked against `_application/data.mjs`, `_application/topical-art.mjs`, `_application/art.mjs` and `_application/rooms.mjs`. Geometry keys such as `commute` and `climate` are stable IDs; prompts follow their actual room content and do not use the old literal labels as scene subjects.
